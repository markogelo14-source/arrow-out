How we make sure every level can be solved

One of the worst feelings in a puzzle game is suspecting the puzzle is broken. If you can't clear a board, you should know it's because you haven't found the answer yet, not because there isn't one. So from day one, we set a rule for Arrowly: every board must be solvable, guaranteed.

Here's how we do it without hand-checking hundreds of levels.

Solving forwards is hard

The obvious approach is to scatter arrows on a grid at random, then run a solver to check whether the board can be cleared. That works, but it is wasteful: many random boards are dead ends, and you throw them away. It also makes it hard to control difficulty.

Building backwards is easy

Instead, we build every board in reverse. Picture the solution as a list of moves: the first arrow you remove, the second, and so on until the last. Now play that list backwards, starting from an empty grid:

  1. Start with an empty board.
  2. Pick an empty cell and a direction.
  3. Only place the arrow if its path to the edge is clear right now.
  4. Repeat until the board is as full as we want.

Why does this guarantee a solution? Each arrow, at the moment we placed it, had a clear path past every arrow already on the board. Those earlier-placed arrows are exactly the ones that will still be on the board when this arrow is removed in the real game, because the game removes them in the opposite order. Arrows added later might sit in its path, but in the real game they are removed first. So removing the arrows in reverse order of placement always works.

for each new arrow:
    pick empty cell + direction
    if path to edge is empty:
        place it
# solution = arrows in reverse order of placement

You can't get stuck either

There's a second, happy property of this game: removing an arrow never blocks anything. It only frees up space. So if a board is solvable at the start, it stays solvable no matter what order you try things in. Bumps cost a heart, but they never put the board into a state you can't solve.

Tuning difficulty

Since the generator always produces solvable boards, we can focus on making them interesting. A few levers we use:

  • Board size and density. Boards start at 4x4 and grow up to 8x10. More arrows on a bigger grid means longer chains of blockers.
  • Arrow length. Arrows can be up to 3 cells long. The same backwards trick works: a long arrow is only placed if the path in front of its head is clear.
  • Free arrows at the start. Boards with only one or two arrows that can leave immediately feel much harder than boards with many.
  • Chain length. The longest sequence of "this frees that" in a board is a good measure of how far ahead you need to think.

We generate many candidate boards, score them on measures like these, and keep the ones that feel right for each stage of the game.
